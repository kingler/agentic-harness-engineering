Component 03 · Tools

What's inside a tool description

JSON the model reads to decide whether to call your tool. Three sentences in description — what / when / when-not — prevent most bogus invocations. The schema is the contract; the exec line is the runnable body.

1Name

Short, verb-led, unambiguous. The model reads this first when picking a tool from the roster.

2Description

UX copy for the model. Three beats: what, when, when not. The "when not" line saves the most failures.

3Input schema

The argument contract. Each field has its own description — that's how the model knows what to pass and what each value means.

4Implementation binding

The harness wires the descriptor to a real command. Tools = JSON face + executable body, glued by the harness loader.
