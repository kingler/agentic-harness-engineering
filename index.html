01System prompt

Persistent context. Prepended to every turn. Survives compaction. Sets persona, scope, and hard rules. 

flowchart LR
    SP["System prompt
(AGENTS.md)"] -.->|prepended| T1[Turn 1]
    SP -.->|prepended| T2[Turn 2]
    SP -.->|prepended| Tn[Turn N...]
    T1 --> T2 --> Tn

File: harness-templates/AGENTS.md

02Rules

Predicates on agent actions. Soft rules live in the system prompt; hard rules live in settings.json allow/deny and hooks. 

flowchart LR
    Intent["Agent intent
(e.g. rm -rf node_modules)"] --> Rules{Rules check}
    Rules -->|allow| Act[Action runs]
    Rules -->|deny| Refuse[Refuse + explain]

Files: AGENTS.md, .roo/rules/, .github/copilot-instructions.md

03Skills

Prompts loaded on demand. The agent doesn't carry every specialist instruction in base context — it loads the skill when a trigger fires. 

flowchart LR
    User[User input] --> Match{"Trigger match?
(e.g. 'design review')"}
    Match -->|yes| Load[Load skill prompt]
    Match -->|no| Plain[Continue without skill]
    Load --> Apply[Apply skill steps]
    Apply --> Reply[Reply]
    Plain --> Reply

File: .github/prompts/design-review.prompt.md

04Tools (scripts)

A stable, named capability the agent invokes via Bash. The script does the work in the world; the agent only reads its stdout. 

flowchart LR
    Agent -->|Bash call| Script["scripts/run-eval.sh"]
    Script -->|read/write| World[("filesystem
tests
APIs")]
    Script -->|stdout| Agent

File: scripts/run-eval.sh + allow rule in settings.json

05Hooks

Bracket every tool call. PreToolUse can refuse; PostToolUse validates, formats, logs. Hooks are deterministic — they always run. 

flowchart LR
    Agent -->|wants tool call| Pre{PreToolUse}
    Pre -->|allow| Tool[Tool executes]
    Pre -->|deny| Block[Block + reason]
    Tool --> Post{PostToolUse}
    Post -->|scope/format/log| Agent

Files: .github/hooks/{pre,post}-tool-use.sh

06MCPs

Typed bridge to an external system. Agent speaks one protocol; the server handles auth, rate limits, and the system's actual API. 

flowchart LR
    Agent <-->|MCP protocol| Server["MCP server
(github, figma, ...)"]
    Server <-->|native API + auth| External[("External system")]

File: mcp.json

07Loops

Observe → act → re-observe, with a hard cap. The cap is the key part: a stuck agent shouldn't keep editing forever. 

flowchart LR
    Start --> Obs[Observe: run tests]
    Obs --> Check{Green?}
    Check -->|yes| Done[Stop: green]
    Check -->|no, retry| Act[Fix first failure]
    Act --> Obs
    Check -->|no, cap hit| Esc[Stop: escalate]

File: .github/prompts/fix-until-green.prompt.md

08Workflows (skill chains)

Named, ordered sequence of skills, subagents, and tools that ships one user-visible outcome. Each step's output feeds the next. 

flowchart LR
    Plan["/plan"] --> Research[researcher]
    Research --> Edit[edit files]
    Edit --> Review[design-review]
    Review --> Fix["/fix-until-green"]
    Fix --> Report[ship report]

File: .github/prompts/ship-ui-change.prompt.md

09Subagents

A child agent with a narrower toolset and its own output contract. How you keep the main context small. 

flowchart LR
    Main[Main agent] -->|delegate| Sub["Subagent
(researcher / critic)"]
    Sub -->|narrow tools| Sources[("docs, code, web")]
    Sub -->|structured brief| Main

Files: .github/agents/researcher.md, critic.md

10Agent teams

Multiple subagents on the same input, in parallel, then merged. Independent perspectives — they must not see each other's drafts. 

flowchart LR
    Input[diff or task] --> R[researcher]
    Input --> C[critic]
    R -->|brief| Merge["Main agent: merge"]
    C -->|issues| Merge
    Merge --> Out[ranked report]

File: .github/prompts/review-team.prompt.md

11Memory

State that survives between sessions. The system prompt is static; memory is read at session start and written during/after. 

flowchart LR
    Start[Session start] -->|read| Mem[("memory/SESSION.md")]
    Mem --> Agent[Agent works]
    Agent -->|append| Mem
    Mem -.persists.-> Next[Next session]

File: memory/SESSION.md

12Domain knowledge

Facts the agent retrieves on demand. Skills tell the agent how to act; knowledge tells it what is true. 

flowchart LR
    Q[Agent question] --> Need{Need a fact?}
    Need -->|yes| KB[("knowledge/*.md")]
    KB -->|cite verbatim| Cited[Answer with citation]
    Need -->|no| Plain[Answer from prompt]

Files: knowledge/README.md, knowledge/style-guide.md

13Evaluation

The regression test for prompts. A model upgrade or skill change can silently break behaviour — evals catch that before it ships. 

flowchart LR
    Cases[("evals/cases/*.json")] --> Run["scripts/run-eval.sh"]
    Run --> Per["per-case JSON: pass/fail"]
    Per --> Diff{Regression?}
    Diff -->|yes| Block[Block ship]
    Diff -->|no| Pass[Ship + log]

Files: evals/, scripts/run-eval.sh

14Learning

How the harness improves between sessions. You don't train the model — you refine the prompts, skills, hooks, and tools. 

flowchart LR
    Logs[("transcripts +
edits.log")] --> Find[Find one pattern]
    Find --> Propose[Propose one change]
    Propose --> Eval[Run evals]
    Eval --> Better{Score improves?}
    Better -->|yes| Merge[Update AGENTS.md / skill]
    Better -->|no| Discard[Discard]

File: .github/prompts/improve.prompt.md

How they compose

The fourteen concepts aren't independent. A real harness layers them on every turn — and improves itself between turns. 

flowchart TB
    User[User turn] --> Main[Main agent]
    Main -.persistent.-> SP["System prompt + Rules"]
    Main -.session start.-> Mem[(Memory)]
    Main -->|may load| Skill[Skill]
    Main -->|may retrieve| KB[(Knowledge)]
    Main -->|may delegate| Team["Team / Subagents"]
    Main -->|may run| Workflow["Workflow / Loop"]
    Workflow --> Tool["Tool / MCP call"]
    Tool --> Hook{Hooks}
    Hook -->|allow| Exec[Execute]
    Hook -->|deny| Block[Block]
    Exec --> Main
    Main -.append.-> Mem
    Main -.transcripts.-> EvalSet[(Eval set)]
    EvalSet --> Learn[Learning loop]
    Learn -.updates.-> SP
    Learn -.updates.-> Skill
