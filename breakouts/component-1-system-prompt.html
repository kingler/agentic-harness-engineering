Component 01 · System prompt

Draft your AGENTS.md

Walk through the five-section system prompt anatomy — identity, scope, hard rules, tool roster, failure modes — with Copilot or RooCode coaching you, scoped to the app you picked to reverse-engineer.

Prerequisites

  • VS Code installed (or your team's compatible editor).
  • GitHub Copilot extension enabled (Pro / Business / Enterprise).
  • RooCode extension installed and signed in.
  • A repo open in VS Code — your team's, or a sandbox is fine.

1Download the template

One zip covers all five breakouts. You unzip it once at the start of Day 1.

Download harness-templates.zip ~45 KB

2Drop it into your repo

# from your repo root
unzip ~/Downloads/harness-templates.zip -d .
cp -r harness-templates/.claude harness-templates/.github .
cp harness-templates/AGENTS.md harness-templates/mcp.json .

You should now see .claude/, .github/, and AGENTS.md at the repo root.

3Pick the app you're reverse-engineering

The slash command is the same. The context you give it is what makes the output feel real.

Harvey · legal AI for law firms

The agent helps lawyers run discovery, review contracts, and trace citation chains. Hard rules are about privilege, source attribution, and the malpractice cost of a hallucinated cite.

Hint: when the slash command asks for hard rules, try:

  • "Every claim about a document must include a pin-cite to a page span."
  • "Never invent case law — if a cite isn't in the loaded corpus, say so."
  • "Privileged matter never leaves the matter's workspace."

Claude for Financial Services · workbook-native copilot

The agent operates inside research workbooks. It pulls filings, builds models, and writes regulatory disclosures. Hard rules are about audit trail, numeric lineage, and SOC 2 / FedRAMP boundaries.

Hint: when the slash command asks for hard rules, try:

  • "Every number in a deliverable must trace back to a cited source row."
  • "Never modify a published workbook without a tracked-change branch."
  • "PII or non-public material info never leaves the firm boundary."

Granola · meeting-native productivity

The agent listens during meetings, builds notes that don't interrupt the conversation, and ships action items. Hard rules are about consent, attendee privacy, and the discipline of not summarizing what wasn't said.

Hint: when the slash command asks for hard rules, try:

  • "Surface a visible recording indicator any time audio is captured."
  • "Action items only — never invent commitments no attendee made."
  • "Drop transcripts on session end; persist only the curated note."

4Run the slash command

Open Copilot Chat or RooCode chat. Type:

/draft-system-prompt

The agent walks you through five questions — one at a time. Don't paste the whole template; let it lead you. Answer in your own words.

What you'll get back. A draft AGENTS.md at the repo root with sections for Identity · Scope · Hard rules · Tools · When stuck. Under 200 lines. If AGENTS.md already exists, the agent writes AGENTS.draft.md for you to diff.

⌘Intro demo — do this in GitHub Copilot

The persona + rules become a custom agent (a reusable Copilot teammate) backed by always-on custom instructions. The slash command writes the same files; this is the native UI your group will drive after the demo.

  1. In the Chat view, click the ⚙ Configure Chat gear → Agents → New custom agent… (or ⌘⇧P → Chat: New Agent File).
  2. Save it to the workspace path .github/agents/<name>.agent.md so it ships with the repo.
  3. Fill the YAML frontmatter — description (when to pick this agent), tools, and optional model / handoffs.
  4. Write the body: your Identity · Scope · Hard rules from AGENTS.md. Reference a tool inline with #tool:<name>.
  5. Pick it from the agent dropdown in the chat input to run the session as that persona. Always-on rules go in .github/copilot-instructions.md (generate with /init).

5Pressure-test the draft

Before you ship it, read the draft as if you were the model trying to argue your way past every rule. Tighten any vague tool name. Re-run /draft-system-prompt with the corrections — it's idempotent.

What's next

When you're happy with AGENTS.md, commit it. Then head back to the deck for Component 2 (Skills) or open the next breakout page directly.
