Component 03 · Tools

Write a tool the agent can pick

The model only sees what's in your descriptor. Walk through the three-sentence WHAT / WHEN / WHEN-NOT pattern, define one input schema, stub the executable body, and ship a tool the agent can actually choose.

Prerequisites

  • VS Code installed.
  • GitHub Copilot extension enabled.
  • RooCode extension installed and signed in.
  • You've completed Component 1 (AGENTS.md) — recommended but not required.

1Download the template

Download harness-templates.zip ~45 KB

2The three flavors of tool

  • Function. Code in the agent's own process. Pick when the capability is a library you already have.
  • Script. Anything you can run from a shell. Pick when the capability is a CLI you already trust.
  • MCP. Borrow someone else's toolset over a protocol. Pick when you don't want to wrap an API yourself.

This breakout focuses on the script-as-tool pattern — JSON descriptor on top, executable body underneath.

4Run the slash command

/draft-tool

The agent walks you through six prompts:

  1. Verb-led name (fetch_filing, not filings).
  2. What — one sentence. Plain language.
  3. When — the trigger pattern in user words.
  4. When NOT — the tempting-but-wrong use. This is the line that saves you most failures.
  5. Input schema — start with one argument.
  6. Stub the script.
The teaching point. Bad tool descriptions are the #1 cause of wrong tool picks. Tool descriptions are UX copy for the model — write them the way you'd write a button label. 
{
  "name": "fetch_filing",
  "description": "Pull an SEC filing by accession number into context. Use when the user asks for a specific 10-K, 10-Q, or 8-K by date or accession. Do not use for non-public corporate matter or for filings older than 1996.",
  "input_schema": {
    "type": "object",
    "properties": {
      "accession_number": { "type": "string" }
    },
    "required": ["accession_number"]
  },
  "exec": "scripts/fetch_filing.sh ${accession_number}"
}

5Pressure-test the pick

Read all your tool descriptions side by side. If the model had to choose between two without context, could it? If not, the descriptions overlap — tighten the WHEN-NOT lines.

What's next

Commit the descriptor and the stub. Then move on to Component 4 (Rules & Hooks) — those are what keep the tool from being misused.
