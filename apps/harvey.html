Harvey

A domain-specific legal AI platform — Vault, Workflows, and Knowledge Sources stitched into a single harness purpose-built for law firms and in-house teams.

Harvey is what an agentic harness as product looks like in a regulated, citation-driven domain. The model is the same one anyone can call — what Harvey ships is the scaffolding around it: a system prompt with privilege and jurisdiction rules, retrieval over a firm's vetted corpus, document tools that read and produce DOCX/PDF artifacts, workflow agents per practice area, and deterministic governance gates that keep outputs auditable. The lessons translate to any vertical where accuracy, traceability, and trust outrank fluency.

What it is

A legal harness, not just a chatbot

Harvey is a domain-specific AI platform marketed to elite law firms, professional-services firms, and corporate legal teams. End users see a chat interface, document drafting, document analysis, research across legal/regulatory/tax sources, and "Workflow Agents" — long-running, multi-step routines that carry out a real legal task (due diligence on an M&A target, a privilege review pass, a contract markup against a firm playbook).

Under the hood, the recipe is: a strong base model plus a layered harness that constrains, retrieves, cites, and governs. The harness — not the model — is the moat. That's the lens this page uses.

Anatomy of the harness

Six slots, mapped to a Harvey-style legal product

The same six slots you'd put in your own harness/ folder appear here — just renamed in legal vocabulary. If you're reverse-engineering Harvey, this is the table you copy into your repo.

Agents · subagents

Workflow Agents per practice area

A main orchestrating agent receives the user's intent, decomposes it, and dispatches to specialist subagents — litigation, transactional, regulatory, in-house — each with its own narrower toolset, system prompt, and output contract.

  • Diligence agent — reads data-room docs, builds an issues list, cites back to source pages.
  • Drafting agent — produces redlines against a firm template / playbook.
  • Research agent — narrow tools for legal/regulatory/tax corpora; never freelances facts.
  • Reviewer / critic agent — re-reads the draft for missed exceptions before it reaches the partner.
Maps to .github/agents/*.md in your harness folder.
Skills

On-demand prompts for legal moves

A skill is a prompt loaded only when its trigger fires — keeps base context small. In a legal harness these are the repeatable "moves" attorneys do every day:

  • privilege-review — scan a document for material protected by attorney-client privilege.
  • redline-against-playbook — mark up a contract against the firm's standard positions.
  • extract-obligations — produce a covenants / deadlines table from a stack of agreements.
  • cite-checker — verify every citation in a brief resolves to a real, on-point authority.
Maps to .github/prompts/*.prompt.md.
Tools · scripts & MCPs

Vault, search, and document I/O

The agent does no work in the world directly — it calls tools. In Harvey-shape, the high-leverage tools are:

  • Vault — read/write into a firm-private document store with permissions enforced server-side.
  • Knowledge sources — typed retrieval over curated legal/regulatory/tax corpora and the firm's own precedents.
  • DOCX / PDF tools — load a Word file, produce a tracked-changes redline back out.
  • DMS / collaboration connectors — iManage, NetDocuments, SharePoint, mobile capture, secure rooms.
  • Web/news search — narrowly scoped, used as a fallback after firm sources, not as a default.
Maps to scripts/*.sh + mcp.json.
Hooks · governance

Deterministic gates the model can't bypass

Hooks bracket every tool call. They're not advice the model can ignore — they run regardless. In Harvey-shape, the hooks enforce non-negotiable legal governance:

  • Privilege gate — PreToolUse: refuse to send privileged material to any non-allowlisted endpoint.
  • Confidentiality scope — PreToolUse: restrict retrieval to matters the user is staffed on.
  • Citation enforcement — PostToolUse: every claim in an answer must resolve to a source token; strip anything that doesn't.
  • Audit log — PostToolUse: append every tool call, doc touched, citation produced, with user + matter ID.
  • PII / out-of-jurisdiction redaction — PreToolUse on outbound web calls.
Maps to .github/hooks/{pre,post}-tool-use.sh.
Knowledge

Source-grounded, cited every time

Harvey doesn't "know" the law — it retrieves it and cites it. Knowledge is structured into layers so retrieval picks the right authority for the question:

  • Public authorities — statutes, regulations, case law, treatises, tax codes; jurisdictionally scoped.
  • Firm precedents — past deals, briefs, memos — the firm's institutional knowledge.
  • Matter context — the documents in the current Vault project the user is working on.
  • Playbooks — firm-standard positions on contract clauses, structured for retrieval not prose.
Maps to knowledge/* + retrieval over a typed index.
Memory

State that survives the session

Two flavors, kept separate so they can be governed differently:

  • Matter memory — facts the agent has already established about this deal/case: parties, key dates, counter-party positions, decisions already made. Persists across the matter's life.
  • User memory — the attorney's preferences: writing voice, drafting conventions, "always cite Bluebook," "default to NY law." Persists across matters.
  • Conversation state — what's been said in the current thread; small, evictable, doesn't outlive the matter.
Maps to memory/SESSION.md + per-matter store.
How they compose on one turn

From "draft a markup" to a defensible artifact

A partner types: "Mark up this NDA against our standard playbook; flag anything that looks non-standard and tell me what we usually accept." Here is the path that turn takes through the harness:

  1. System prompt & rules load — Harvey persona, privilege rules, citation requirement, "never fabricate a clause."
  2. Skill match — the request triggers redline-against-playbook; its prompt is loaded.
  3. Memory read — pulls the user's preferred writing voice + the playbook version they're on.
  4. Knowledge retrieval — fetches the firm's playbook for NDAs and any matter context already in Vault.
  5. Subagent delegation — drafting agent produces the redline; reviewer agent re-reads it independently.
  6. Tool calls — DOCX tool emits a tracked-changes Word file back into Vault.
  7. Hooks run — citation hook verifies every "we usually accept X" is grounded in a playbook entry; audit log appended.
  8. Memory write — counter-party name + matter facts appended to matter memory for the next turn.
Trade-offs

Why this works, and where it breaks

Why this works

Trust in legal output is non-negotiable: a hallucinated case kills a brief. The harness pushes every accuracy guarantee out of the model and into deterministic infrastructure — retrieval, citation, hooks, audit — so the model only has to be fluent, not correct about the world. That's a tractable contract.

Where it breaks

When the knowledge layer is thin (a niche jurisdiction, a new statute, an unusual deal type), the agent has nothing real to cite and may stall or over-hedge. Workflow agents also brittle-fail at seams between practice areas (a deal with tax + regulatory + IP angles) when no orchestrator owns the cross-cutting view.

For your breakout

If you picked Harvey — reverse-engineer this

  • System prompt: write the 1-page AGENTS.md that bakes in jurisdiction, privilege, and "cite every claim."
  • Skills: name three legal skills and write the trigger phrase + 5-step body for one of them.
  • Tools: list the four tools you'd allow. For each, write the single line of stdout it returns.
  • Hooks: draft the PreToolUse rule that refuses to send privileged content to a non-allowlisted endpoint.
  • Knowledge: sketch the four layers (public · firm · matter · playbook) and the one rule for which gets searched first.
  • Memory: decide what goes in matter memory vs user memory vs ephemeral conversation state.
