Component 04 · Rules & Hooks

Wire policy to enforcement

Rules say what's allowed. Hooks make sure it actually holds. Walk through the allow / deny / ask triad in settings.json, then pair it with a pre-tool-use hook that fires every time.

Prerequisites

  • VS Code installed.
  • GitHub Copilot extension enabled.
  • RooCode extension installed and signed in.
  • jq on your $PATH — the hook script uses it.

1Download the template

Download harness-templates.zip ~45 KB

2The triad — strong vs weak rules

Weak: "Be careful with secrets." The model can't check that.

Strong: "deny": ["Read(./.env*)"]. The harness checks it.

Three lists do the work:

  • allow — explicit yes-list. Anything not listed defaults to ask.
  • deny — hard refusals the harness enforces. The model can't argue past these.
  • ask — gated actions that require a human nod.

3Pick the app + the risky surface

Harvey · candidate rules

  "Read(./matters/{matter_id}/**)",
  "Bash(grep -r:*)"
],
"deny": [

  "Write(./deliverables/**)"
]

Hook predicate: block any read of a matter folder other than the active matter — privilege boundary.

4Run the slash command

/draft-rules-hooks

The agent will:

  1. Walk you through naming 2–3 patterns for each of allow / deny / ask.
  2. Write .claude/settings.json with the triad + a hooks.PreToolUse pointer.
  3. Ask you for one mechanical check the hook should enforce.
  4. Write .claude/hooks/pre-tool-use.sh with that check + emit structured block / approve JSON on stdout.
  5. chmod +x the hook so the harness can actually run it.
Hook decision contract. Stdout JSON of the form {"decision":"block","reason":"…"} or {"decision":"approve"}. Exit code 0 means the decision is honored; non-zero means the hook itself failed and the harness applies its default. Be loud on failure — silent hook errors silently lose enforcement.

⌘Intro demo — do this in GitHub Copilot

Rules in Copilot are custom instructions (path-scoped with an applyTo glob). The "must hold every time" half is a hook — a folder under .github/hooks/ that runs a script around tool use. Instructions advise; hooks enforce.

  1. Always-on rules → .github/copilot-instructions.md (scaffold with /init). Run ⚙ Configure Chat → Instructions → New… for scoped ones.
  2. Path-scoped rules → .github/instructions/<name>.instructions.md with an applyTo: glob so they load only on matching files.
  3. For "every time" enforcement, add a hook: .github/hooks/ with a hooks.json + a pre-tool-use script.
  4. The script inspects the pending call and emits {"decision":"block","reason":…} or {"decision":"approve"} — be loud on failure.
  5. chmod +x .github/hooks/*.sh so Copilot can actually run it. The model can't argue past a hook.

5Pressure-test as the model

Read your deny list as if you were the model trying to argue your way past. Where's the wiggle room? Tighten the pattern, then re-run.
