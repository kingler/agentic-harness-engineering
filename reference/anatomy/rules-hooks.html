Component 04 · Rules & hooks

What's inside the policy layer

Two halves of the same idea. Rules declare what's allowed, denied, or gated — the policy. Hooks run the rule — deterministic shell scripts that fire before or after every tool call. Scroll either section; the matching callout lights up.

04a · Rules

What's inside a rules file

Permissions live in .claude/settings.json. Allow / deny narrows the blast radius before a single tool fires; the hooks block wires deterministic enforcement on top.

    "allow": [
      "Read",
      "Edit",
      "Bash(git status:*)",
      "Bash(git diff:*)",

      "Bash(git reset --hard:*)"
    ]
  },
  "env": {
    "WORKSHOP_HARNESS": "v0.1"
  },

    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/post-tool-use.sh" }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/pre-tool-use.sh" }
        ]
      }
    ]
  }
}
1Allow

Explicit yes-list. Anything not listed defaults to ask — fewer surprises, smaller blast radius.

2Deny

Hard refusals the harness enforces. The model can't argue its way past these — and shouldn't be able to.

3PostToolUse hooks

Run AFTER a matching tool finishes. Use for side effects the harness should always perform — bump timestamps, run validators, log telemetry.

4PreToolUse hooks

Run BEFORE a matching tool. Returns block/approve. Defence in depth on top of the deny list, for combinations a glob can't express.

04b · Hooks

What's inside a hook

Shell scripts the harness fires before or after every tool call. The event payload arrives as JSON on stdin; the script's exit code (and optional stdout decision JSON) tells the harness whether to proceed.

Real-world example · pre-tool-use hook

pre-tool-use.sh — full file

Lives in

└── .claude/

#!/usr/bin/env bash
# PreToolUse hook — runs before every Bash tool call.
# Bound in .claude/settings.json under "PreToolUse" matcher "Bash".
#
# Goal: refuse a small set of obviously-destructive commands even if
# the user (or the model) asked for them. The deny list in
# settings.json catches the common ones; this hook adds a defense-in-
# depth layer for combinations.

set -euo pipefail

# Hook input arrives as JSON on stdin
payload="$(cat || true)"
cmd="$(printf '%s' "$payload" | jq -r '.tool_input.command // empty' 2>/dev/null || true)"

if [[ -z "$cmd" ]]; then
  exit 0
fi

deny_patterns=(
  'rm[[:space:]]+-rf[[:space:]]+/'
  'rm[[:space:]]+-rf[[:space:]]+\$HOME'
  'mkfs\.'
  ':(){[[:space:]]*:|:&[[:space:]]*};:'
  'curl[[:space:]]+.*\|[[:space:]]*sh'
  'wget[[:space:]]+.*\|[[:space:]]*sh'
)

for p in "${deny_patterns[@]}"; do
  if printf '%s' "$cmd" | grep -Eq "$p"; then
    echo "pre-tool-use: refused dangerous command pattern: $p" >&2
    exit 2
  fi
done

exit 0
# Exit 0 = decision honored. Non-zero exit = hook error,
# the harness logs and falls back to default policy.
1Event payload

The harness pipes JSON in on stdin: tool name, args, session id. The script reads what it needs and ignores the rest.

2Deny patterns

An array of ERE regex patterns. Anything matching is refused. The list is short by design — six patterns covers most catastrophic shapes.

3Match loop

The predicate. Iterate, regex, refuse. Keep it mechanical — if a check needs nuance, it belongs in a rule, not a hook.

4Exit semantics

Zero = decision honored (approve). Non-zero with stderr = block with reason. Be loud on failure — silent hooks are worse than no hook.
