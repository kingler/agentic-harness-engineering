Component 05 · Knowledge & Memory

Two tiers of what the agent remembers

knowledge/ is the slow tier — facts that change quarterly. memory/ is the fast tier — state that changes per session. Draft one of each and learn what stays where.

Prerequisites

  • VS Code installed.
  • GitHub Copilot extension enabled.
  • RooCode extension installed and signed in.
  • memory/ added to .gitignore if your team's policy is "session memory never lands in git."

1Download the template

Download harness-templates.zip ~45 KB

2The two tiers

  • knowledge/ — durable facts the agent retrieves on demand. Schemas, dictionaries, workflows. Changes quarterly.
  • memory/ — volatile working state. The current session's working set, scratch decisions, what the user just said. Changes per turn.

Conflating them is the #1 anti-pattern. Volatile state in knowledge/ ages badly; durable facts in memory/ get truncated away.

3Pick the app + the durable fact

Harvey · candidate knowledge files

  • knowledge/citation-format.md — Bluebook citation schema, with verbatim rules for pin-cites.
  • knowledge/privilege-log.md — the firm's privilege-log column schema.
  • knowledge/matter-glossary.md — internal abbreviations the model doesn't know.

Belongs in memory, not knowledge: "the matter we're working on right now," "the deposition coming up Thursday."

Claude Financial Services · candidate knowledge files

  • knowledge/disclosure-schema.md — required sections for a Reg-FD compliant disclosure.
  • knowledge/lineage-rules.md — how a numeric must trace back to a source row.
  • knowledge/workbook-conventions.md — named-range conventions used across decks.

Belongs in memory, not knowledge: "this quarter's revenue assumption," "the analyst asked for sensitivity on EBITDA margin."

Granola · candidate knowledge files

  • knowledge/meeting-types.md — taxonomy of recurring meeting shapes (1:1, standup, review).
  • knowledge/action-item-format.md — required fields for any extracted action (owner, due, source line).
  • knowledge/customer-glossary.md — product names, internal codenames the model doesn't know.

Belongs in memory, not knowledge: "who's on this call," "what the host wants us to focus on this hour."

4Run the slash command

/draft-knowledge

The agent walks you through both files in one pass:

  1. Pick the app and name the durable fact.
  2. Knowledge frontmatter — applies_to path glob + last_reviewed date.
  3. Citation rule — verbatim for contracts, paraphrase for prose.
  4. Write knowledge/{topic}.md.
  5. Switch to the fast tier — write memory/SESSION.md with working-set bullets.
  6. The carve-out — name one thing you were tempted to put on the wrong side.
The mental model. "If a bullet survives multiple releases, promote it from memory/ to knowledge/." Run that test on anything you write in memory/SESSION.md at the end of the session.

5Pressure-test the carve-out

Open both files side by side. For every bullet, ask: does this change quarterly or per-session? If quarterly, it belongs in knowledge/. If per-session, memory/. Move anything that's in the wrong file.

What's next

Commit knowledge/{topic}.md. Decide whether memory/ is gitignored. Head back to the deck for the wire-up exercise.
