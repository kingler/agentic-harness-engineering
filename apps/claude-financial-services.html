Claude for Financial Services

A verification-first vertical for banking, insurance, asset management, and fintech — native in Excel and PowerPoint, with agent templates that trace every number back to a source.

Claude for Financial Services is Anthropic's vertical harness wrapped around Claude. It is the same model anyone can call from the API — what makes it a product is the scaffolding: Excel / PowerPoint add-ins, agent templates for modeling and reporting, deterministic governance for SOC 2 and FedRAMP postures, and pre-built MCP-style connectors to the market and identity data partners analysts already pay for. Reverse-engineering it is a clean exercise because every concept in the workshop maps to a concrete file you'd put in your own harness/ folder.

What it is

Vertical Claude, built for the second-line review

Financial services products fail not on fluency but on auditability. A number in a credit memo, a figure in a pitch deck, a covenant in a diligence summary — every one of these has to trace back to a verifiable source the institution already trusts. Claude for Financial Services is built around that constraint: it lives where analysts already work (spreadsheets, decks), it cites every number, and it gives risk & compliance a deterministic trail to follow.

The product surface is small. The harness behind it is the bulk of the value.

Anatomy of the harness

Six slots, mapped to a regulated vertical

Same six slots as every harness in the workshop — renamed in the vocabulary of a buy-side / sell-side / carrier team.

Agents · subagents

End-to-end financial agents, with handoffs

A main agent receives the analyst's request and delegates to specialists that own a single workflow end-to-end. Each has a narrower toolset and a structured output the next agent (or human) can consume.

  • AML / investigations agent — pulls KYC + transaction trails, drafts a SAR narrative, hands to compliance.
  • Credit decisioning agent — assembles financial spreads, peer comps, covenant tests; produces a credit memo skeleton.
  • Fraud / payments agent — explains an alert in plain English with the underlying signal as evidence.
  • Portfolio ops agent — quarter-end roll-forward, exception list, variance commentary.
  • Reviewer / verifier agent — independent re-read against the same sources; flags anything the drafter asserted without citation.
Maps to .github/agents/*.md in your harness folder.
Skills

On-demand prompts for finance moves

Skills are loaded only when their trigger fires — keeps base context lean even as the catalog grows. In a financial harness these are the routine moves analysts do every week:

  • trace-this-number — for any figure in a draft, surface the cell / table / filing it came from.
  • build-comp-set — pull comparables for a target by sector / size / geography.
  • spread-financials — normalize statements from a 10-K / 10-Q into the firm's template.
  • variance-commentary — write Q-over-Q or Y-over-Y narrative bounded to verified deltas.
  • diligence-question-set — generate a question list for a target from a CIM.
Maps to .github/prompts/*.prompt.md.
Tools · scripts & MCPs

Excel, PowerPoint, and the data partners

The product lives in the surfaces analysts already use, and reaches the data sources their risk function has already vetted. The tools are the wire from the agent to those surfaces.

  • Excel add-in — read a range, write a range, preserve formulas, attach source notes to cells.
  • PowerPoint add-in — assemble slides from approved templates, lock the "data & sources" footer.
  • Market & identity MCPs — LSEG, FactSet, S&P Global, Morningstar, Moody's, Dun & Bradstreet, and similar.
  • Filings & news — typed retrieval over EDGAR, sanctions lists, and industry feeds.
  • Internal systems — risk warehouse, CRM, order management — all MCP-shaped, all auth'd server-side.
  • Python sandbox — for ad-hoc spreads, never against production data.
Maps to scripts/*.sh + mcp.json.
Hooks · governance

Enterprise assurance, enforced not asked for

Hooks are deterministic — they run before/after every tool call regardless of what the model decided. In a regulated vertical, they are the difference between a product the risk function will sign off on and one it won't.

  • SOC 2 / FedRAMP boundary — PreToolUse: only let MCP calls leave to allowlisted endpoints.
  • Material non-public info gate — PreToolUse: block outbound research on tickers the user is restricted on.
  • Source-attribution enforcement — PostToolUse: every number in an output must carry a citation token; strip or refuse otherwise.
  • Audit log — PostToolUse: append a tamper-evident record of every tool call, doc, citation, user, and ticker touched.
  • Capital-markets & client-facing gate — PreToolUse: any action that could leave the firm (file a doc, send a memo, hit an order surface) requires an explicit human approval token.
Maps to .github/hooks/{pre,post}-tool-use.sh.
Knowledge

Auditable lineage from signal to narrative

Knowledge is layered so retrieval picks the right source for the question — and so every figure can be walked back to its origin.

  • Market data — prices, fundamentals, ratings; vendor-attributed.
  • Filings — 10-K, 10-Q, 8-K, prospectuses; structured for retrieval, not just full-text.
  • Identity & reference — issuer / counterparty / beneficial-owner data.
  • Internal records — your firm's positions, exposures, prior memos, client interactions.
  • House view — research notes, model parameters, methodology docs — for tone & framing.
Maps to knowledge/* + retrieval over a typed index.
Memory

What carries across, what doesn't

Three flavors, governed separately because their risk profile differs.

  • Mandate memory — facts established about this deal, account, fund, or matter: parties, exposures, decisions taken, sign-offs received. Lives with the engagement.
  • User memory — analyst preferences: default sector, comp methodology, writing voice, "always run a covenant headroom check." Lives with the user.
  • Conversation state — short-lived; evicted on session close; never retained for regulated outputs.
Maps to memory/SESSION.md + a per-mandate store.
How they compose on one turn

From "give me a credit memo skeleton" to an audited draft

An analyst types: "Build a credit memo skeleton for Target Inc. Pull the last three years, peer set from the sector add-in, and flag covenant headroom under our standard tests." Here is the path that turn takes through the harness:

  1. System prompt & rules load — verification-first stance, "cite every number," restricted-list guard.
  2. Skill match — spread-financials, build-comp-set, and variance-commentary are loaded.
  3. Memory read — the analyst's preferred comp methodology + their firm's covenant template.
  4. Knowledge retrieval — last three filings via the filings index; peers via the market-data MCP.
  5. Subagent delegation — credit-decisioning agent drafts; verifier agent independently re-checks every figure.
  6. Tool calls — Excel add-in writes the spread sheet; PowerPoint add-in produces the memo with locked footers.
  7. Hooks run — SOC 2 boundary check, restricted-list check, citation enforcement, audit-log append.
  8. Memory write — facts about Target Inc. (covenant terms, lead bank, deal stage) recorded against this mandate.
Trade-offs

Why this works, and where it breaks

Why this works

Risk & compliance can see the harness. Every number is cited, every tool call is logged, every restricted-list breach is a hook-deny rather than a model judgement call. That is what makes the product deployable into a regulated stack at all.

Where it breaks

The harness is only as good as the data partnerships behind it. If the institution doesn't already license LSEG / FactSet / S&P / Moody's coverage of the asset class, retrieval falls back to public filings and the analyst is doing the synthesis. The harness also can't help when the analyst's question is fundamentally judgement ("is this a good deal?") rather than retrieval.

For your breakout

If you picked Claude Financial Services — reverse-engineer this

  • System prompt: write the 1-page AGENTS.md that bakes in verification, citation, and restricted-list awareness.
  • Skills: name three finance skills; write the 5-step body for trace-this-number.
  • Tools: list the four tools you'd allow; for each, write the JSON shape it returns.
  • Hooks: draft the PreToolUse rule that refuses outbound research on a restricted ticker.
  • Knowledge: sketch the five layers (market · filings · identity · internal · house view) and the rule for which is searched first.
  • Memory: decide what goes in mandate memory vs user memory vs ephemeral state — and which one risk wants logged.
