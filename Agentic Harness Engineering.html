Foundations

The core formula

AGENT = MODEL + HARNESS
Agent

The emergent behavior

Goal-directed, tool-using, self-correcting entity the user experiences.

Model

The intelligence

Takes in text and images, outputs text. That's it.

Harness

Everything else

Code, config, tools, constraints that make the model useful.

"If you're not the model, you're the harness." — Vivek Trivedy · LangChain

System prompt & tools

01

System Prompt & Instructions

The persona, rules, and constraints you give the model.

Design decisions
  • Tone & personality of the agent
  • What it should / shouldn't do
  • AGENTS.md / CLAUDE.md files
  • Skills as progressive disclosure
Designer leverageHigh
02

Tools, Skills & MCPs

The actions the agent can take in the world.

Design decisions
  • Which tools to expose (fewer = better)
  • Tool descriptions (UX copy for agents)
  • MCP server connections
  • Permission boundaries & confirmations
Designer leverageVery high

Anatomy

Hooks & feedback loops

05

Hooks & Middleware

Deterministic logic around the agent.

Key insight. When something should happen every time, don't rely on the model to remember — enforce it with code.
Examples
  • Auto-lint after every code edit
  • Safety checks before tool execution
  • Context compaction at thresholds
06

Feedback Loops

How the harness improves over time.

The improvement cycle
  • Traces — understand failure modes
  • Evals — the "training data" for the harness
  • Self-verification — agent checks its own work
  • Hill-climbing — iterative harness optimization

Agent time: designing input architecture

Designers influence what the agent knows across three temporal dimensions.

Past

What the system has already captured

  • Preferences & goals
  • Prior decisions
  • Conversation history
  • Learned patterns
Present

What is happening right now

  • Current state
  • Active constraints
  • Real-time signals
  • User context
Future

How the agent adapts based on inputs

  • Predicted needs
  • Proactive suggestions
  • Continual learning
  • Harness optimization

Exercise 2

Design a harness challenge

Scenario A

Travel Agent

Plans trips, books flights, manages changes in real-time.

Scenario B

Design System Agent

Maintains consistency, reviews PRs, generates components.

Scenario C

Customer Support Agent

Handles tickets, escalates issues, learns from history.

Deliverables

  1. Harness component map — all 6 components defined
  2. State diagram — key user intents → agent actions
  3. One critical design decision & the tradeoff you're making

Pro tips

  • Start with the user intent, not the tech
  • Ask: what should happen every time vs. what the model should decide?
  • Fewer tools = better performance (too many MCPs make agents dumb)
  • Design the failure state first

Takeaways

Your harness engineering toolkit

01

Agent = Model + Harness.

You're always designing the harness, even if you don't call it that.

02

Start with intent-system maps, not wireframes.

Model the state transitions first.

03

Write tool descriptions like UX copy.

They're the interface between the agent and its capabilities.

04

Design for determinism where possible.

Hooks > hoping the model remembers.

05

Most agent failures are input failures.

Design the data capture architecture carefully.
